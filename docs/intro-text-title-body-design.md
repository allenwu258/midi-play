# 入场文字：标题／正文与可调描边设计及实现说明

状态：v0.4.10 的核心功能已实现。本文记录 `83404a3` 后的标题／正文与描边扩展，于 2026-10-23 根据代码审查更新；不表示所有视觉验收项目均已通过。已知差异和待验证项见第 6、7 节。

## 1. 目标与范围

入场文字由单段升级为“标题＋正文”的组合文字块，两部分分别设置字号，共用字体、描边、内部对齐、文字块宽度、画布位置、显示时间与退场动画。标题和正文作为一个整体预览、拖动和退场。

当前已实现两个多行纯文本输入区、两个字号控件和公共描边粗细设置。独立字体、颜色、字重、独立动画轨道、富文本和多个自由文字块不在本次范围内。

预览与最终视频继续使用同一个 `IntroTextAsset` 实现。没有引入 FFmpeg drawtext、浏览器排版、新 Vulkan shader 或额外文字渲染线程。配置仍只保存在当前曲目的进程内草稿，不写入项目文件或设置文件。

## 2. 当前配置规则与默认值

几何参数均以 1280×720 参考画布为基准，随输出分辨率等比缩放；时间以成品视频时间线为准。

| 项目 | 当前规则 | 默认值 |
| --- | --- | --- |
| 标题 | 多行纯文本，允许显式换行和自动换行，可为空 | 空；占位提示“作品名称” |
| 正文 | 多行纯文本，用于词曲、演奏和说明等，可为空 | 空；占位提示“作词：… / 作曲：… / 演奏：…” |
| 标题字号 | 独立整数值，12–160 基准 px | 48 |
| 正文字号 | 独立整数值，12–160 基准 px | 32 |
| 字体 | 两部分共用，由 Qt 处理字体回退 | Microsoft YaHei |
| 描边粗细 | 0.0–4.0 基准 px，步长 0.1；0 表示关闭 | 0.8 |
| 文字颜色／描边颜色 | 白色／黑色 alpha 220 | 固定 |
| 标题与正文间距 | 两部分都有非空白内容时使用；否则为 0 | 12 基准 px |
| 内部对齐 | 左／中／右，同时作用于两部分 | 居中 |
| 文字块宽度 | 画布宽度的 20%–90%，两部分共用 | 80% |
| 画布位置 | 居中／左下／自定义中心偏移 | 居中 |
| 自定义偏移 | X 向右、Y 向下；面板范围 X ±1280、Y ±720，仍需通过画布边界校验 | X=0、Y=0 |
| 完整显示 | 0–600 秒 | 5 秒 |
| 退场用时 | 0.1–5 秒 | 1 秒 |
| 退场效果 | 淡出／向下滑出并淡出 | 淡出 |

标题不强制大于正文；两者可以相同或反向设置。0.8 已是代码默认描边宽度，仍需补充真实字体与亮暗背景下的视觉比较。

### 内容、空值与校验

1. 启用文字时，标题和正文至少一部分包含非空白字符，否则显示“请输入标题或正文，或关闭此选项。”；关闭时跳过文字校验。
2. 全空白部分不参与文档排版、不占高度，也不产生两段间距；输入内容保留在面板草稿中。正文首行不会被自动拆成标题，也不会从文件名填入标题。
3. 校验和排版将 CRLF／CR 规范化为 LF；对参与排版的部分保留显式空行与空格，不自动截断、缩小字号或调整位置。
4. 先检查规范化后的两部分合计 UTF-16 长度不超过 16000，再分别计算 grapheme cluster，合计最多 2000 个。
5. 当前显式行限制的实现为：两部分换行数之和达到 50 时拒绝。它尚未按两部分各自的段落数求和；两部分均有内容且换行总数为 49 时，可通过这一项检查但对应 51 个显式段落。原设计的“合计最多 50 个显式段落”仍是待统一的规则，不能视为已实现。自动折行另受整体画布边界约束。
6. 两个字号、描边、宽度、时长及枚举值均有校验。文字块的布局矩形超出参考画布时阻止导出并保留输入，用户需要调整内容、字号、宽度或位置；此处校验尚不包含实际字形墨迹边界，见第 6 节。

### 控件与窗口尺寸

- 标题与正文均使用 `QPlainTextEdit`，最小／最大高度分别为 54／78 和 86／110 逻辑像素；各自字号放在对应标签右侧。编辑框使用 UI 字号，输出字号仅影响预览和成品。
- 描边 slider 使用 0–40 整数刻度，数值框显示 0.0–4.0、一位小数。两者通过 `QSignalBlocker` 同步，配置保存整数十分位。0 显示为 `0.0 px`，旁边固定提示“0 为无描边”，没有单独开关或特殊值文案。
- 字号与描边控件后缀均为 `px`；字号工具提示和描边说明解释 720p 参考画布单位。更换输出分辨率不回写基准参数。
- 右栏最小宽度为 320，包含独立滚动区。“完整显示”和“退场用时”当前固定为上下两行，未实现随宽度切换为并排布局。
- 展开时优先宽度至少为 1150，并按左右栏布局 `sizeHint()` 的较大高度计算所需窗口高度；未展开时按左栏测量。尺寸限制在屏幕可用区域减去预留空间以内，两栏均保留滚动兜底，不保证小屏或高 DPI 下所有设置同时可见。
- 左侧预览最大为 512×288，右侧内容增加不会修改这一上限。深浅主题沿用应用样式；真实多 DPI 下的完整可见性尚待验证。

### 编辑、预览与草稿

- 修改内容、字号、字体、宽度、对齐、位置和描边时停止播放并进入布局模式，经过 150ms 防抖更新文字资产；拖动与方向键定位即时同步。
- 从时间预览返回布局模式时，必要时请求第 0 帧背景。布局模式下后续文字样式修改复用背景，不因文字修改重建 Vulkan 会话或解码器。
- 标题和正文共用一个选框，拖动整个文字块；方向键移动 1 基准 px，Shift＋方向键移动 10 基准 px。
- 居中锚定组合块中心；左下锚定逻辑矩形左侧 64、底部 684；自定义锚定中心 `(640, 360)` 加 X/Y。从预设切换到自定义时，在旧配置可成功准备的情况下保留当前可见位置。
- 显示时间、退场时长与效果作用于整个组合块，预览无声。切换 FPS 保持输出时间并量化到新帧率，短片中不可达的退场快捷时点禁用并提示动画截断。
- 取消勾选保留标题、正文和样式草稿；取消对话框不保存，接受视频导出才保存到当前曲目草稿，切换曲目清空。切换到音频页或隐藏对话框会停止播放并释放预览资源。

## 4. 配置与组件职责

### 值对象

`src/app/introtextconfig.h` 已将旧 `text`／`fontPixelSize` 字段替换为以下明确字段，其余公共布局和时间字段保留：

```cpp
struct IntroTextConfig {
    bool enabled = false;
    QString titleText;
    QString bodyText;
    QString fontFamily = QStringLiteral("Microsoft YaHei");
    int titleFontPixelSize = 48;
    int bodyFontPixelSize = 32;
    int outlineWidthTenths = 8; // 0..40，基准画笔总宽度的 1/10 px
    // alignment / position / offsets / width / timing / effect
};
```

整数十分位避免缓存比较与 slider 同步时的浮点误差，UI 和渲染边界再除以 10.0。当前字号、描边范围常量在面板和渲染文件中分别定义，默认值也存在于配置及面板回退值中；数值目前一致，尚未完成原设计提出的共享常量收敛。

配置没有磁盘持久化，因此本次没有项目文件迁移或 legacy 字段。未来如增加项目存储，需要另行设计版本化序列化。

## 5. 排版、描边与缓存实现

### 组合布局

`introtext.cpp` 内部的 `TextLayout` 保存 title／body 两个文档、各自是否参与排版、各自高度及组合尺寸。空部分不执行文档排版。

1. 规范化文本，判断各部分是否含非空白内容。
2. 组合宽度为 `1280 × widthPercent / 100`，两部分文本宽度均为组合宽度减去左右各 8px 边距。
3. 各部分使用独立 `QTextDocument`、独立像素字号及公共字体／对齐；文档 margin 为 0。使用 design metrics、四个空格宽度的 tab stop 和 `WrapAtWordBoundaryOrAnywhere`。
4. 标题在上、正文在下，均存在时插入 12px。组合高度为两文档高度之和，加条件间距及上下各 8px 边距。
5. `validationError()` 和需要重新排版的 `prepare()` 共用 `layoutText()`，按组合逻辑矩形校验画布边界。
6. 将文档分别平移到相应位置，绘入同一张静态透明 `QImage`。使用 `setPlainText()`，用户输入中的 `<b>` 等内容不会被解释为 HTML。

### 描边语义与实际绘制顺序

对外数值为画笔总宽度，直接对应 `QPen::widthF`，不是字形外扩半径。画笔使用逻辑坐标，输出缩放由 painter 统一完成：

`输出画笔宽度 = outlineWidthTenths / 10.0 × outputWidth / 1280`

例如默认 0.8 基准 px 对应 1080p 的 1.2px、4K 的 2.4px。画笔使用默认的非 cosmetic 模式、黑色 alpha 220、圆端点和圆连接。宽度为 0 时不设置 `TextOutline`，避免 Qt 将零宽画笔解释为设备像素 hairline。

当前为每个文档设置白色 foreground 和可选 `TextOutline`，再调用一次文档布局的 `draw()`。原设计中的“描边绘制后再独立覆盖白色填充”双 pass 尚未实现；不能将白色内部不受描边影响列为已验证保证。所有文档绘制仍仅发生在 asset 栅格化阶段，不进入逐帧编码循环。

### 缓存与有效状态

- 栅格缓存键包含原始标题、正文、两个字号、字体、内部对齐、宽度、描边及输出尺寸。任一变化重新排版并生成图像。
- 仅位置、显示／退场时间和效果变化可复用静态图像；位置变化按相同布局尺寸重新检查画布边界。
- `prepare()` 开始即将资产标记为无效，成功后才恢复。配置校验失败时可能保留旧图像内存，但 `paint()` 不会继续显示它；关闭文字会清空图像和边界。
- 输出尺寸需为有效 16:9、最高 3840×2160。导出先准备一次 asset，再根据输出帧时间应用整体淡出／向下滑出；完全消失后的合成直接返回，不创建 painter。

## 6. 已知差异与待验证风险

以下为 2026-10-23 代码审查的记录；本次文档更新没有修复对应实现。

| 项目 | 当前事实／风险 | 后续验证或处理目标 |
| --- | --- | --- |
| 字形及描边边界 | 组合几何依赖文档尺寸和固定 8px 边距；`drawDocument()` 的 `PaintContext.clip` 使用文本宽高，未显式计算 glyph ink bounds、描边外扩和抗锯齿余量。大描边、特殊字体或边缘字形存在裁切风险，尚无完整复现实验 | 使用真实字体检查自动折行、边缘位置、特殊字形和最大描边；根据结果统一绘制边界、预留空间与校验 |
| 白色填充 | 单次 `TextOutline` 绘制与原双 pass 方案不同；现有测试未验证粗描边时字形内部白色区域 | 比较细笔画在 0／0.1／0.5／0.8／1.0／2.0／4.0 下的像素及视觉结果，再决定是否增加填充覆盖 pass |
| 显式段落上限 | 只累加换行，未计入两部分各自的首段，双段可能放行 51 段 | 统一“50 行／50 个显式段落”的产品规则与计数，并补充临界用例 |
| 范围与默认常量 | 面板、渲染器和配置中仍有重复定义 | 后续修改范围时同步核对，或提取共享契约 |
| 窗口与 DPI | 双栏测高、屏幕限制、两栏滚动已实现；没有完成真实 Windows 100%／150%／200% 缩放验收 | 检查长字体名、错误提示、输入框、时间参数和输出路径的可见性及滚动可达性 |

## 7. 验证记录与剩余验收

### 已运行的检查

2026-10-23 代码审查中复跑了 `build/intro-text-title-body-outline-20261023/Release/midi_play_intro_text_tests.exe`，二进制生成时间晚于本次相关源码。使用 offscreen 平台并补齐 Qt 运行库搜索路径后，普通模式与 `--integration` 模式均以退出码 0 结束。

- 普通模式覆盖标题／正文组合、仅标题／仅正文、独立字号、描边变更后图像更新、空值及范围校验、动画时间、整体拖动、FPS 转换和对话框生命周期等用例。
- 输出尺寸用例覆盖 512×288、720p、1080p 和 4K 的准备成功、锚点及文字块宽度比例，不等同于各分辨率下的实际墨迹边界或细描边视觉验收。
- 描边用例比较 0 与 3.0 的图像差异和整体像素范围，没有完整验证零描边黑色像素、白色内部填充及全部粗细边界。
- 布局用例检查深浅主题。在 800×800 的 offscreen 可用屏幕上，窗口受限后使用滚动兜底，输出路径可滚动到达；这不代表真实高 DPI 的视觉验收。
- 集成模式执行真实视频导出／解码比较：640×360、30FPS、200% 速度、向下滑出，检查首帧可见、退场中仍可见、结束后消失及帧数一致；还覆盖预览 seek、播放／暂停、路径校验解耦及预览资源释放／恢复。
- 审查时 `git diff --check` 通过，仅有 LF／CRLF 行尾提示。本次文档更新未重新编译、打包或运行测试。

### 尚未完整验收

- 最大描边、末尾换行、显式空行、实际 glyph overhang 和画布边缘位置的完整像素检查。
- 不同粗细下白色字形内部的保留程度，以及亮暗背景、中英字体、回退字体和复杂脚本的视觉表现。
- 双段合计 50 个显式段落的临界计数，以及无效配置恢复有效配置的专项回归。
- 新字段在真实编辑中的 IME 组合输入、两部分分别清空后恢复及草稿取消／接受／切曲场景的专项验证。
- 60FPS、淡出效果及其他分辨率下的真实编码对照；现有布局／动画单元用例不能替代全部编码组合。
- Windows 真实深浅主题、100%／150%／200% 缩放与小屏滚动；当前版本的 Traditional-only 构建验证。无 Vulkan 或缺少 FFmpeg 的集成用例应报告跳过，不能当作通过。
