# 音符色彩模式：视觉设计与开发方案

日期：2026-09-16。分析基线：`main` / `v0.3.3` / `52647fc`。

本文件保留设计依据与验收计划；功能已在 `feat/note-color-modes` 实现，实际验证结果及性能边界见第 8 节。

## 1. 产品目标与范围

新增全局设置“音符色彩”，包含“普通”和“鲜明”，默认鲜明。选择立即生效并自动持久化，不需要重新打开文件或重新启动。

- 普通：保持 v0.3.3 在相应界面主题下的颜色、透明度、材质和密度处理行为。
- 鲜明：增加同一轨道内的协调色彩变化，提高主体色彩的纯净度和辨识度，保持轻淡尾迹和克制的击键反馈。
- 界面主题与音符色彩相互独立，支持深色/浅色 × 普通/鲜明四种组合；更换主题不改变已选色彩模式。
- 新安装和缺失该配置项的旧版本用户默认鲜明；用户选择普通后，后续启动始终尊重已保存的普通设置。
- 应用于传统 Qt 与 Vulkan，包括下落音符、按键高亮和击键光晕。现有简谱数字、八度点和其他文字继续使用主题文字色，保证阅读对比。

沿用既有方角外形、按键/踏板时长语义、音符宽度、重叠分道、简谱显隐与判定位置。简谱隐藏时继续隐藏整条黄线及其背景光带。保留已有局部击键反馈的行为；本功能不添加新的粒子系统、全屏光效、呼吸动画或动态变色。

## 2. 截图与代码说明了什么

### 2.1 当前颜色链路

| 层级 | 当前实现 | 与本需求的关系 |
| --- | --- | --- |
| 音乐投影 | `PlaybackVisualizationProjector` 的 10 色 `kTrackPalette`，按轨道序号循环赋给 `VisualTrack.color` | 音轨数量少时，全画面基本只有一两个主色 |
| 音符语义 | `VisualNote` 已携带 pitch、velocity、staff、voice、flags、trackIndex 及三种时间 | 新模式所需信息已具备，不需要重新解析 MIDI/MusicXML |
| 材质计算 | `makeNoteMaterial()` 将轨道 RGB 转为 OKLab 色相，再按音域、声部和力度构造各层颜色 | 已具备感知色彩计算基础，应扩展它而不是在两个后端分别调颜色 |
| 样式去重 | `noteMaterialKey()` 使用轨道、`pitch / 6`、声部、力度桶和 ghost | 现有缓存不能直接支持逐音级配色 |
| Qt | `NoteRenderCache` 创建渐变，`NoteRasterCache` 缓存横向纹理条，QPainter 合成 | 普通/鲜明需正确触发材质版本失效 |
| Vulkan | `VulkanScene` 将相同材质写入实例，GLSL 处理形状、渐变覆盖和时间 | 模式变化需刷新音符实例，不能只更新 QWidget |
| 动画反馈 | `NoteFrameState` 选择按键主导音符，生成强度、光晕和全局主体衰减 | 琴键和光晕要与新颜色同步，但不能改变播放判定 |

具体定位：`playbackvisualizationprojector.cpp:20/167`、`notematerial.cpp:72/80`、`noterendercache.cpp:49/128`、`noteframestate.cpp:81`、`vulkanscene.cpp:17/56`。行号为上述基线。

### 2.2 单调的成因

1. 轨道主色决定大多数视觉印象。当前同轨道音高变化主要是每六个半音改变一次色相，音域总偏移限制为 ±21°，普通 MIDI 通常缺少丰富的 staff/voice 区分。连续旋律容易落在相同颜色桶里。
2. 力度主要影响亮度和透明度，不能提供明显的色相层次。仅提高饱和度会得到更艳的同色大片，仍然缺乏变化。
3. 浅色普通主体的 OKLCH 色度为 0.125，alpha 为 `0.66 + 0.12 × v`；深色分别为 0.115、`0.43 + 0.12 × v`。横向渐变又乘以 0.66～1～0.78，高密度再衰减主体。最终看到的颜色比材质数值更淡。
4. 长音和踏板延音属于不同视觉语义。当前长主体表示按键时长，较细尾迹表示松键后仍可听的延音；截图中长色块不能全部解释为渲染缺陷，也不宜为装饰而截短、分段或改写时值。

截图本身不足以确定 MIDI 轨道、左右手或声部对应关系。方案只使用文件明确提供的音乐字段，不根据屏幕左右位置推断演奏分工。

## 3. 视觉策略

### 3.1 选择“轨道色系 + 音高配色”

| 策略 | 优点 | 局限 | 决策 |
| --- | --- | --- | --- |
| 只增加现有饱和度 | 改动最少，轨道色明确 | 同轨仍单调，长音更易形成色墙 | 不作为完整方案 |
| 全曲固定十二音级彩虹 | 单轨也有丰富颜色 | 轨道色识别变弱，连续半音/和弦容易显杂 | 不采用机械彩虹 |
| 按每个音符随机选色 | 色彩数量多 | 破坏重复、seek 和声部的视觉稳定性 | 不采用 |
| 轨道拥有协调色系，音级在系内变化 | 保留轨道风格，同时给旋律增加层次 | 需要精细缓存身份与双主题调校 | 推荐 |

鲜明模式采用偏清透的宝石色：青碧、湖蓝、靛蓝、紫罗兰，以及适量琥珀、珊瑚、玫红色系。鲜艳来自有控制的色度、明暗和对比，不依赖满屏高饱和色、大面积白色高光或粗描边。

每条轨道分配一个含三个协调色相锚点的色系，按照音级在相邻锚点间取样。整条旋律保留家族特征，但不再只有一种蓝或一种绿。第一阶段保持与现有轨道序号循环规则一致，避免增加声部识别、调性分析等不稳定依赖。

可用于初轮校准的 10 组 OKLCH 色相角如下；这是可调的设计数据，不是行业标准，也不是已经验证的最终参数。

| --- | --- | --- |
| 绿 | 150 / 178 / 207 | 翡翠—青碧—湖青 |
| 蓝 | 224 / 260 / 296 | 湖蓝—靛蓝—紫罗兰 |
| 金黄 | 56 / 78 / 98 | 琥珀—金黄—黄绿 |
| 珊瑚 | 12 / 30 / 50 | 玫珊瑚—朱红—暖橙 |
| 紫 | 278 / 306 / 334 | 蓝紫—紫罗兰—莓红 |
| 青 | 175 / 203 / 233 | 碧青—湖青—蓝 |
| 橙 | 30 / 52 / 74 | 珊瑚橙—琥珀—金 |
| 草绿 | 122 / 145 / 169 | 嫩绿—翠绿—碧绿 |

超过十条轨道仍可能复用色系，不能声称每条轨道都拥有唯一可辨识颜色。同一文件中保持稳定，不保证文件重新编排轨道后颜色身份不变；这与现有分配边界一致。

### 3.2 逐音符映射规则

旋律音符的计算顺序：

1. 由 trackIndex 选择固定色系，非法轨道使用明确的青色回退色系。
2. `pitchClass = pitch % 12`，用固定查找表获取 `u ∈ [0,1]`。
3. 在三个色相锚点间按最短色相弧分段插值；跨 0° 必须正确环绕，禁止直接 RGB 混色产生灰色中间色。
4. 八度只引入很小的明度差，初始建议每八度 0.01、总偏移不超过 ±0.025，保持跨八度的同音级联系。
5. 已有声部桶仅带来轻微偏移，控制在数度以内；普通 MIDI 没有相关元数据时保持中性。不将 staff/voice 自动解释为左右手。
6. 沿用力度桶与重音规则。力度主要提高亮度及主体存在感，色度只做有限调节；弱音仍需清楚可见。
7. ghost 保持弱化语义；按键时长、踏板延音时长不参与色相计算。

初始十二音级查找表（C 至 B）：

```text
u = [0.12, 0.26, 0.48, 0.70, 0.90, 1.00,
     0.86, 0.66, 0.42, 0.20, 0.00, 0.02]
```

该表让音级在一个色系内往返变化，避免在 B→C 时发生整色系的突跳，同时使常见和弦中的不同音具有层次。它仅表达审美关系，不宣称音级和颜色存在客观对应，也不根据未知调性给 MIDI 推断音阶功能。初轮必须同时审查半音音阶、大小三和弦和连续琶音，避免只对单个示意片段调色。

对同一轨道、音高、力度桶、声部和 ghost 状态，颜色确定且可复现；重复音允许同色。颜色不依赖当前帧、播放顺序、seek 次数、窗口尺寸、可见音符集合、随机数、源音符 ID 或展开后的实例 ID。重复段和并列同音不通过实例序号“重新抽色”。

打击乐不套用旋律音级色表。按 GM 乐器类别选择固定变体：底鼓、军鼓/边击、踩镲、通鼓、镲片分别取色系内不同位置；未知编号使用中性变体。映射表覆盖已支持的 GM 编号，不靠编号取模冒充音乐语义。

### 3.3 普通/鲜明与深浅主题

普通保留现有计算路径和数值。鲜明使用独立材质配置，主题只改变视觉适配，不改变音符的色系和音级角色。

以下为进入真实渲染迭代的起始区间，全部为色域映射前参数；不直接当作固定验收值。

| 层 | 深色鲜明 | 浅色鲜明 | 目的 |
| --- | --- | --- | --- |
| 主体 | L 约 0.70～0.78，C 0.16～0.21，alpha 0.78～0.88 | L 约 0.54～0.62，C 0.16～0.21，alpha 0.78～0.88 | 深色上清亮，浅色上保持色彩浓度 |
| 音头/触键边 | L 约 0.82～0.87，保留色相，较高 alpha | L 约 0.42～0.49，使用同色系较深色 | 有清晰起音边，但不形成粗黑描边 |
| 踏板尾迹 | 较低 C、alpha 约 0.15～0.22 | 较低 C、alpha 约 0.20～0.28 | 大片延音不抢主体注意力 |
| 按键高亮 | 独立 keyFill/keyTop 配置 | 独立 keyFill/keyTop 配置 | 保证白键、黑键上均可读 |
| 局部击键光晕 | 同一音符色相、既有面积/寿命上限 | 同一音符色相，控制大面积铺色 | 反馈连贯，不增加全屏闪动 |

继续使用 OKLCH→线性 RGB→sRGB、超色域减小 C 的处理方式。第一阶段复用现有映射算法以保护普通模式基线；不顺带更换混合空间、交换链格式、曝光或 gamma。

所有材质对外输出 straight-alpha sRGB；Qt 的预乘纹理和 Vulkan 片元输出各在自己的边界预乘一次。不能把“提高鲜艳度”实现成重复乘 alpha、改用加法混合或无约束提高 RGB。

### 3.4 长音、高密度及微动画

- 主体、2.5 DIP 音头、宽度比例 0.38 的踏板尾迹继续使用方角；保留横向渐变和亚像素覆盖，保证窄音符平滑移动。
- 不把长音切成装饰色段，不用运动渐变改变长音颜色；先通过主体/音头/尾迹的层级解决板块感。
- 普通保留现有 `clamp(1/(1+coverage*0.42),0.52,1)`。鲜明可从系数 0.38、下限 0.62 起步校准，只影响已有每帧主体/尾迹透明度标量，不改变配色身份。
- 当前密度值依赖可见面积，会随播放变化；先保持其连续公式，不增加基于帧历史的缓动器，以保证 seek、暂停截图和双后端的确定性。是否进一步平滑须以实测的亮度跳变为依据。
- 不让小范围高密度改变所有音符的色相；不把透明度下限提高到接近全不透明。
- 沿用 attack 180 ms、release 240 ms、主导音符选择及现有光晕数量上限。首次实现只同步色彩，不扩大光效数量和覆盖面积。
- 同音高多轨同时发声仍取现有主导音符作为按键反馈来源，不临时把不同颜色平均成灰色。需要记录并测试主导音符切换时的自然色彩交接；它与未按下整排琴键闪烁不同。

本轮不引入模式切换交叉淡化：跨两份材质的持续插值会增加缓存和 GPU 生命周期复杂度。用户主动切换后，下一次可绘制帧完整使用所选模式即可。

## 4. 设置与持久化

设置页面在“界面主题”附近新增一行“音符色彩”，用现有 QComboBox 风格，包含“普通”“鲜明”。默认值由配置模型控制，不能依赖选项顺序。简短说明：普通“柔和、统一的轨道配色”；鲜明“更鲜艳的协调配色，同轨音符具有色彩层次”。提示立即生效并自动保存。

不在主窗口增加模式按钮，不增加饱和度、色相等专业参数。设计示意中的调校工具只供方案讨论，不是新增的产品设置。

新增 `domain/settings/notecolormode.h`：

```cpp
enum class NoteColorMode : int { Normal = 0, Vivid = 1 };
inline constexpr NoteColorMode kDefaultNoteColorMode = NoteColorMode::Vivid;
```

提供 isValid/normalize/fromPersistent/toPersistent 函数和 Qt metatype。数值一旦落盘保持稳定，不通过界面文本或 combo index 持久化。

`PlayerSettings` 添加 `noteColorMode`，schema 从 6 升到 7。持久化键使用 `General/noteColorMode`，保持现有配置命名约定。

| 场景 | 行为 |
| --- | --- |
| 新安装、旧配置缺失键 | 鲜明，不告警，不重置其他偏好 |
| 有效 Normal=0 / Vivid=1 | 尊重已存选择，与 schema 值独立读取 |
| 非整数、越界、损坏值 | 回退鲜明并提示；保留可读取的其他设置 |
| 用户重复选择当前值 | 无重复信号、无材质失效、无不必要保存 |
| 用户选择其他模式 | 立即生效，然后按既有服务模式保存 |
| 保存失败 | 当前会话保留所选外观，明确显示未保存；重启使用实际落盘值 |
| 配置被成功修复保存 | 已解决的加载告警不再在后来新建的设置窗口中误报 |

加载只读取，不为展示默认值而强制写配置。使用 Qt 信号阻断器同步控件，避免初始化或回填选中项触发保存循环。深浅主题、刷新率、图形模式、简谱显隐、标题栏和音源路径必须原样保留。

新增模式同时处理相关告警生命周期，避免复制已有“历史加载告警在修复后仍显示”的问题；不得在保存失败时提前清除警告。失败后重新尝试保存是否成功须有实际返回结果，不能仅凭界面已变色判断。

### 5.2 缓存身份：本功能最重要的正确性条件

不能只在 `makeNoteMaterial()` 增加 `pitch % 12`，却继续用 `pitch / 6` 的旧键去重。这样一个桶中的首个音符会错误决定其他音级的颜色，也会让结果依赖音符出现顺序。

采用两个模式共用的完整样式键，建议显式 `NoteStyleKey` 值结构及一致的 equality/qHash：

```text
trackIndex + exact MIDI pitch + voiceTint bucket
           + effective velocity bucket + ghost + percussion
```

八度、音级和打击乐类别均从 pitch 推导，不重复存冗余字段。声部与力度必须使用材质计算相同的归一化函数。以后每增加一个会影响材质的输入，都需要检查键是否覆盖；哈希值相同不代表身份相同，必须保留相等比较。

chart 身份和 appearance 由缓存实例整体持有，不必复制到每个样式键；模式和主题变化通过 materialRevision 管理。只对实际出现的组合建样式，不预分配轨道×128×声部×力度×ghost 的笛卡尔积。

两个模式都采用同一细粒度分组，可在 normal→vivid→normal 时只重算样式，不重新扫描全部音符分配 styleIndex，也不改变 PreparedNoteRenderData 的几何/时间。普通模式虽然分组变细，材质公式仍按旧的音域桶计算，保持视觉基线。

性能代价必须明确：纯旋律样式键的音高粒度从每六音一组变成逐音，实际样式数最坏可能接近原来的六倍，并不是“零成本切换”。正常逐帧渲染仍不计算 OKLCH；开曲/外观切换按去重后的样式数量计算。

### 5.3 Qt 消费层

- `FallingNotesView::setNoteColorMode()` 规范化输入、保存至场景状态、向存在的 Vulkan 子窗口传递并请求刷新。
- 模式单独变化不标记布局或静态琴键图像为脏；按键的动态着色从新材质取值。
- `NoteRenderCache::prepare()` 比较完整 appearance。chart 不变时，只重建材质并推进 materialRevision。
- `NoteRasterCache` 已追踪 materialRevision，可沿用失效条件和 16 MiB LRU；失效后按实际绘制样式惰性生成横向纹理。
- 渐变系数、绘制顺序、裁剪和形状首先保持既有行为。第一轮视觉目标无需新增 shader primitive 或修改渐变 ABI。

### 5.4 Vulkan 消费层

当前 `VulkanScene::prepare()` 通过 `themeChanged` 刷新音符。扩展时改为观察缓存的 materialRevision，统一覆盖主题、色彩模式及未来材质参数变化：

```text
cache.prepare(chart, geometry, appearance)
materialsChanged = lastConsumedMaterialRevision != cache.materialRevision()
if candidatesChanged || layoutChanged || materialsChanged:
    rebuildNotes(state)
    lastConsumedMaterialRevision = cache.materialRevision()
```

这里 notesRevision 对应 GPU 音符实例，与 CPU chartBuildCount、geometryBuildCount 是不同层面的“重建”。模式切换可以重新打包候选音符颜色，但不能因此重建音乐投影和音符布局。

- 模式单独变化：音符批次刷新；动态按键/光晕颜色更新；静态 UI 与字体图集保持原版本。
- 主题变化：静态 UI 仍按既有逻辑更新，同时刷新音符；模式选择不被主题重置。
- 首次创建 Vulkan 后端、切回 Qt、Vulkan 初始化失败回退都继承当前模式，避免恢复默认造成跳色。
- 模式变化不销毁窗口、Vulkan device、swapchain 或 pipeline。CPU 输出最终 sRGB 材质，GLSL 不重做音级映射及 OKLCH 转换。
- 沿用已有 `bodyOpacity` push constant 传递密度结果。保持 straight-alpha 到片元输出的一次预乘。
- 必须保留 per-swapchain-image 可变资源、静态/动态/音符缓冲分离、render-pass dependency 和 `completePresentation()` 保护。颜色设置不是修改这些机制的理由。
- 不通过 device idle 每次强制清空流水线来保证换色。各交换链资源按既有版本和安全完成机制更新，允许已提交帧自然排空，但不允许一张新帧中的音符/琴键混用两个材质版本。

- Vulkan 模式变化刷新 notesRevision、动态高亮；静态 UI 和字体图集不变；主题+模式连续变化保持一致。
- 测试基线显式指定 Normal。不能让新默认值 Vivid 悄悄改变原测试的含义，然后仅更新快照“消除失败”。

### 6.3 真实播放与双后端

基础画面矩阵：2 主题 × 2 色彩模式 × 2 后端 × 2 简谱状态，共 16 种组合；在代表场景中再覆盖 DPR 1/1.5/2。

样本至少包括：用户《如愿》MIDI、单轨钢琴、半音音阶、琶音、大小和弦、长按键+长踏板、多轨同音重叠、打击乐、MusicXML 声部/连音/装饰音/颤音/歌词，以及超过十轨的密集曲目。检查 ghost 和低力度音符是否在浅背景上消失，暖黄是否对比不足，紫蓝是否被色域映射压成近似同色。

视觉验收同时评估主体中心、音头、尾迹、网格叠加和活跃琴键；不以色卡 RGB 或一个全画面均值作为美观/可读性证明。首轮参考目标：普通力度孤立音符的主体中心对背景至少约 2:1、音头约 3:1；抗锯齿边缘和刻意弱化的 ghost/尾迹单独评估，不强行套用正文文字的对比度标准。

Qt/Vulkan 比较使用相同时间点、视口、DPR 和设置；分别计算音符、头部、琴键内部及背景区域误差，并目视检查边缘。抗锯齿边界允许合理差异，普通模式在同后端、同环境对比 v0.3.3，应保持像素基线。

必须增加真正的设置入口集成验证：先加载有效 SoundFont 和乐曲、确认 `session() != nullptr`，再通过设置切换。在播放、暂停、seek 后分别检查 session 身份、播放状态、时间按预期推进、倍速、节拍器和窗口句柄保持。对实时播放应检查单调性与容差，不断言切换前后的时间戳完全相同；不能再以两个空指针相等证明会话保持。音频设备不可用的环境明确跳过硬件验证，Windows 实机补齐。

Vulkan 连续压力场景保持至少原有 4096 音符级别，交错进行模式/主题/简谱切换、seek、resize、最小化恢复与后端回退。主连续阶段不逐帧 grab 或等待 GPU，以免掩盖同步问题；启用 synchronization validation，要求零错误，并采样未按下琴键稳定性。普通和鲜明都要验证。
